= Implementation plans — index

This folder holds **detailed, actionable plans** for work that is **not yet implemented** or only partially implemented in the repository.
It complements link:../explanation/vision-and-constraints.adoc[vision and constraints] (product direction) and link:../../CHANGELOG.adoc[CHANGELOG] (what shipped).

== How to use these documents

. Pick a plan by area (table below).
. Each plan states **current state**, **target state**, **phased work**, **dependencies**, and **acceptance criteria**.
. Update the plan file when scope shifts; add a short entry to `changelog-details/` when a phase completes if the change is non-trivial.

== Cross-cutting themes

These appear in multiple plans; keep them consistent across documents.

* **Local-first and minimal trust in hosts:** anything “cloud” is opt-in and explicit.
* **Interchange:** prefer link:../../spec/openapi/prv-local.openapi.yaml[OpenAPI] + link:../../spec/json-schema/exchange-bundle.schema.json[JSON Schema] as contracts before ad hoc JSON.
* **Provenance:** VCs, hashes, and append-only or versioned events should agree across desktop, extension, and web where the same data is shown.
* **Regulatory posture:** certification programs (HIPAA tooling, FDA SaMD, etc.) stay **out of scope** until a deliberate program exists; plans must not imply certification by shipping a feature flag.
